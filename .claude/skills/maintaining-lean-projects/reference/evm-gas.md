# Gas optimisation of verified EVM bytecode

Lessons from eth-act/ml-dsa-fv, 2026-11-02 to 04: hand-written ML-DSA-44/65/87 verifiers (EIP-8355 interface, compressed key, real SHAKE, no helper contracts) generated by Python (`scripts/gen_opt.py`). v3 → v4: 1.04–1.09× on today's EVM; a Glamsterdam build: 1.20–1.26×. Both were then formally proved (`proof-campaigns.md`); every gas change is a re-proof, so weigh savings against the subroutines it touches.

## Workflow

1. **Profile per subroutine** on a fixed vector: self gas and call counts (a Python EVM with per-pc gas, mapped to the layout's pc ranges). In ML-DSA-44, Keccak was 58% and the NTTs 10%.
2. **Compute two floors before promising a number.** An op-count floor (only the operations the algorithm must do, 3 gas each, no stack moves) and a realistic floor per kernel. The paper floor (1.7–1.8×) was never reachable; the realistic estimate (1.22–1.27×) matched the result (1.25×). Correct a wrong estimate to the user as soon as you see it.
3. **One agent per area, owning separate generator functions**, each with a timebox and a "stop below 1% (or 10% per kernel)" rule. Areas that worked: non-Keccak tuning, worst case and long messages, packing schedule, arithmetic kernels, Keccak kernel schedule, and a pure prototyping lab for new representations.
4. **Every change behind a new generator version.** The proved bytes stay byte-identical (SHA-pinned in the selftest); new bytes go to their own directory. List the changed subroutines (diff modulo relocation): each one is a re-proof.
5. **Merge branches into one candidate yourself** and re-measure; savings measured on different bases don't simply add.

## Techniques that paid

- **Fuse passes over memory**: accumulate A·ẑ once per word instead of once per column (−24k to −81k); fuse UseHint into the inverse NTT's last pass.
- **Bias to skip reductions**: store z + 8q so butterflies drop their +2q; Shoup multiplication for constant zetas. Assert every interval bound in the generator or selftest; those assertions become the proof lemmas.
- **Search, don't hand-tune, bit networks and stack schedules**: a 7-stage delta-swap network for byte swap plus spread (found by search, asserted at generation time); a shortest-path search over stack schedules for the Keccak round (each deep swap parks one value and fetches the next): 35,340 → 33,562 gas per 4-state permutation, within 0.6% of its realistic floor.
- **Pack parallel work to the floor**: four Keccak states per 256-bit word (bit-interleaved, so one 256-bit rotation rotates all four). Let a state migrate between slots (a few thousand gas) to reach ⌈permutations / 4⌉ calls: ML-DSA-44 25 → 23 calls (−84k).
- **Use free slots for rare-but-real work**: running μ's blocks in idle SIMD slots made messages up to 613 bytes need no extra Keccak call (−64k to −155k for |M| ≥ 70). Check every message length after a schedule change; one schedule made |M| ≥ 342 dearer and needed a run-time switch.
- **New EIPs**: EIP-8024 (DUPN/SWAPN/EXCHANGE, 3 gas) lets the 25-lane Keccak state live on the stack instead of memory (−12% per kernel); EIP-7954 (65,536 B code) allows unrolling. Unrolling alone saved only 0.3%.
- **Rotation by memory**: storing a word twice (addr, addr+32) makes `MLOAD(addr+k)` a free byte rotation. An 8-way layout with every rotation byte-aligned reached 8,565 gas per state (−15% per state), but didn't fit 24,576 B with everything else and wasted slots; prototype before integrating.

## Ruled out (don't re-try without new facts)

- KECCAK256 opcode for SHAKE: zero initial state, fixed padding, 4 output lanes.
- BLAKE2F: a different function. MODEXP Kronecker tricks: Â is sampled in the NTT domain. TSTORE: dearer than memory.
- MULMOD rotation: wrong on all-ones words; the corrected version costs more (13.4k per state).
- Packed 64-bit lanes, 32-bit halves with shift rotations, next-round parity fused into chi: all slower per state.
- Mask-free Montgomery, radix-4, Plantard, lazy product reduction, 8×32-bit lanes for the NTT: no gain in 64-bit lanes.
- Calldata advice or an expanded key: changes the interface. Real 2× needs an EVM change (a Keccak-f opcode, roughly 3.5× for ML-DSA-44 by estimate).

## Validation (all of it, every step)

- Selftest on all vectors for old and new versions, with SHA pins for proved bytes.
- A second and third EVM: revm (forge) on the full corpus, the execution specs (EELS) for new forks, and the Lean model's exact gas where it exists.
- Fuzz with fresh keys; a worst-case harness that measures each data-dependent routine on its most expensive path.
- **Force rare paths with debug builds.** A schedule change left stale words in a buffer that only a failing-SampleInBall path read; it ran out of gas instead of returning 0. Every test missed it; only the formal proof found it. Add a test that forces each reject path, and check it fails on the broken build.
- Watch code size: v4 87 was 23,798 B against 24,576.
